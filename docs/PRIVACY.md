# Экспериментальная приватность

Все настройки выключены по умолчанию и хранятся отдельно для устойчивого Telegram user ID. MOROK не обещает состояние «всегда офлайн»: отправка сообщения, звонок, серверная логика и другая активная сессия могут раскрывать присутствие. Подавление online/read/typing конфликтует с пунктом 1.4 правил Telegram API; отдельная настройка не устраняет этот конфликт.

## Фактическая реализуемость

| Поведение | Состояние в этой версии | Ограничение |
|---|---|---|
| Штатные настройки «Последняя активность» Telegram | Сохранены | Серверная политика Telegram; MOROK её не подменяет |
| Набор, запись, загрузка, выбор стикера | Реализовано локальное подавление | Семантический gate в `MessagesController.sendTyping`; результат со второго аккаунта ещё не проверен |
| Emoji interaction / просмотр интерактивной emoji-анимации | Реализовано локальное подавление | Обычный центральный action и отдельная отправка taps охвачены |
| Cancel typing | Всегда разрешён | Нужен, чтобы включение режима не оставляло прежний индикатор до timeout |
| Speaking in group call | Не подавляется | Это часть работающего call signaling, а не обычный индикатор набора чата |
| Server-required bot draft cleanup | Не подавляется | Служебное завершение draft должно сохранять согласованное состояние |
| Online status | Штатное поведение | Отдельный lifecycle/reconnect hook ещё не реализован и не проверен |
| Read receipt и локальный read cursor | Штатное поведение | Нужна отдельная модель локального/серверного cursor и проверки уведомлений |
| Content read для voice/video | Штатное поведение | Не объединяется с обычным read receipt |
| Story view | Штатное поведение | Реакции и ответы также могут раскрыть просмотр |
| Отправка сообщения без появления online | Не заявляется | Требуются собственный API ID и наблюдение вторым аккаунтом |

Пресет «Призрак» сейчас включает только реализованную политику набора. Индивидуальный переключатель «Не показывать набор и запись» хранится отдельно: отключение пресета не стирает выбранную вручную политику. Экран прямо перечисляет оставшееся штатное поведение и не показывает переключатели для ещё не подключённых функций.

Gate возвращает `false` до создания MTProto request и до изменения локального `sendingTypings`. Он не отбрасывает произвольные пакеты, не подделывает успешный ответ сервера и при ошибке чтения настроек сохраняет обычное поведение Telegram. Быстрый ответ из уведомления, ChatActivity, voice/video recording, upload progress и sticker selection используют центральный путь. Прямые call/bot actions рассмотрены отдельно в таблице.

Проверка на JVM покрывает выключенные defaults, независимость пресета и индивидуальной настройки, разрешение cancel, reset, schema downgrade и разделение аккаунтов. Компиляция Android подтверждает совместимость hook/UI. Фактическую видимость для собеседника нужно проверить вторым аккаунтом на другом устройстве после настройки собственных Telegram API credentials.
