# Профили приложения

Экран `Настройки Морока → Профили Морока` объединяет уже подключённые локальные настройки. Каждый встроенный или сохранённый профиль сначала показывает точные значения, а записывается только после кнопки «Применить профиль».

| Профиль | Оформление | Автовоспроизведение видео / GIF | Приватность | Текст сообщения в уведомлении |
|---|---|---|---|---|
| Обычный | Как в Telegram: Liquid Glass включён, минимум эффектов выключен | включено / включено | обычное поведение Telegram | показывается |
| Скрытный | Без прозрачности | выключено / выключено | пресет «Призрак» | скрыт |
| Рабочий | Как в Telegram | выключено / выключено | обычное поведение Telegram | показывается |
| Экономный | Без прозрачности и минимум эффектов | выключено / выключено | обычное поведение Telegram | показывается |

Во всех четырёх встроенных профилях сохраняются выбранное качество кружочков, текущий direct/manual/auto маршрут, список исключений приватности для отдельных чатов и настройки [безопасности](SAFETY.md). Профиль не меняет серверные notification preferences, не создаёт MTProto request и сам по себе не отправляет read или online-status event.

«Сохранить текущие как Свой» фиксирует оформление, качество кружочков, глобальные privacy-флаги, автовоспроизведение видео/GIF и показ текста уведомлений. Идентификаторы аккаунта и чатов, Telegram auth, прокси, архив и Память в сериализованное состояние не входят. При применении «Своего» списка исключений чатов остаётся текущим. Состояние принадлежит устойчивому ID вошедшего пользователя; slot аккаунта идентификатором не считается.

Перед применением синхронно сохраняется предыдущее управляемое состояние. «Вернуть предыдущие настройки» применяет этот снимок, поэтому им можно переключаться между двумя последними состояниями. Это серия записей в несколько существующих хранилищ: при обычной runtime-ошибке код пытается вернуть исходные значения, но операция не является crash-атомарной при принудительном завершении процесса или потере питания.

Оформление и LiteMode autoplay являются настройками устройства Telegram, а privacy и notification-content override привязаны к аккаунту. Поэтому применение профиля одного аккаунта меняет общие для установки оформление и autoplay. Сохранённые «Свой» и «Предыдущие» изолированы по устойчивому ID пользователя.

Скрытие текста действует в двух общих путях сборки Telegram-уведомлений и отдельно заменяет story push на общий текст нового сообщения. После локальной записи NotificationsController перестраивает уже активные уведомления через свой штатный `showNotifications()`; server update не вызывается. Штатные настройки preview для диалога и типа чата продолжают действовать. Имя отправителя или название чата может остаться видимым; содержимое сообщения и истории не показывается. Проверка с реальным FCM, вошедшим аккаунтом, lock screen и вторым аккаунтом остаётся обязательной до беты.

Pure-Java тесты проверяют матрицу встроенных режимов, сохранение качества кружочков и сети, определение текущего режима, строгий versioned codec и повреждённые входы. Source-интеграционный тест удерживает обе notification-точки, устойчивый account namespace, порядок сохранения previous до применения и отсутствие сетевых/server API в менеджере профилей.
