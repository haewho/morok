# Память Морока: первая реализованная вертикаль

Это локальные карточки, которые пользователь создаёт командой **«Запомнить»** в меню долгого нажатия обычного сообщения. Это начало реализации разделов 4 и 13 задания, **не полный автоматический архив всех полученных сообщений**. Карточка содержит полученную цитату, источник и отправителя, TL-снимок с entities/reply/media metadata, заметку, строку тегов, явную отметку «Нужно ответить», состояние завершения и локальное напоминание. Экран доступен из настроек Морока.

## Что работает в коде

- Одна карточка на устойчивый ключ `authorizedUserId / peerKind / peerId / messageId / topicId`. `peerKind` различает пользователя, обычную группу и канал/супергруппу. Номер слота Telegram не является владельцем данных.
- Повторное ручное сохранение открывает существующую карточку. После явного удаления автоматическое наблюдение её не создаёт заново. Повторная команда «Запомнить» — новое явное разрешение сохранить этот источник.
- Отдельный экран текущего аккаунта: «Всё», «Нужно ответить», «Отложено», «С файлами», «Завершено», поиск по тексту всех сохранённых версий, заметке, тегам, названию чата/отправителя и имени файла. Поиск выполняется в фоновой очереди; строки списка переиспользуются RecyclerView.
- Доступные обычные фото и документы копируются в приватное хранилище, шифруются и сохраняются независимо от Telegram-кеша. Память сама ничего не скачивает и не запрашивает сеть. Для документа проверяется полный объявленный размер. Thumbnail не используется как замена оригинала.
- Для файла видны состояния: оригинал не скачан, сохранён, превышает лимит, недоступен, ошибка места/ключа. «С файлами» включает также карточки с отсутствующим оригиналом. Кнопка «Повторить из локального кеша» доступна в карточке и у отдельной версии: она восстанавливает защищённые серверные метаданные, заново проверяет eligibility/identity и ищет только уже готовый файл Telegram, не вызывая загрузку. Состояния загрузки/миниатюры отдельным UI в этой версии не реализованы, поскольку Память загрузку не ведёт.
- «Открыть сохранённый файл» выдаёт выбранному приложению временный доступ только для чтения одного файла. `ContentProvider` не экспортирован, URI случайный, доступ ограничен десятью минутами и текущей сессией. Проверяются AEAD и SHA-256; расшифрованные байты идут через pipe, без открытого временного файла на диске. Выбранный просмотрщик получает содержимое по явному действию и может иметь собственный кеш. Переиспользование URI после logout не открывает новую сессию.
- При выборе источника проверяется тот же устойчивый пользователь. Обычный ChatActivity открывается с явным account, peer/message, и локально известной темой через ForumUtilities. Если аккаунт вышел или тема ещё не известна локально, показывается состояние ошибки. Поиск/редактирование карточки не отправляет read receipt. Явное открытие исходного чата использует обычное поведение Telegram, включая чтение.
- Локальное напоминание использует AlarmManager `setAndAllowWhileIdle`, без разрешения точных будильников и без бота. Изменение/завершение карточки отменяет соответствующее уведомление; удаление карточки/очистка отменяют напоминания. BOOT_COMPLETED, TIME_SET, TIMEZONE_CHANGED и запуск приложения восстанавливают расписание из зашифрованных карточек. Время хранится как абсолютный момент; смена зоны меняет отображение, а не выбранный момент. Doze и ограничения Android могут задержать доставку, что явно указано в UI. Если уведомления/канал запрещены, UI предлагает настройки, а уже заданное напоминание остаётся ожидающим. Заблокированные уведомления повторно проверяются не чаще чем раз в шесть часов.
- Уведомление содержит общий текст без цитаты и имени отправителя. Его нажатие проходит через обычную блокировку LaunchActivity и открывает карточку правильного аккаунта; сам показ уведомления не открывает и не читает чат.

## Автоматический архив и наблюдение за изменениями

Экран «Локальный архив сообщений» хранит политику по устойчивому ID авторизованного аккаунта. Автоархив по умолчанию выключен. Для работы нужны одновременно включённый account-switch и явно выбранный личный чат, группа/супергруппа либо канал; список ограничен 256 dialog ID. Выключение сохраняет список для следующего включения и не удаляет уже зафиксированные снимки.

`MessagesController.processUpdateArray` передаёт новые `MessageObject` выбранных чатов в Memory до штатного `putMessages`. Разрешённые снимки одной входной пачки сначала фиксируются в `journal.tink`, после чего Telegram всегда продолжает свою обычную запись и обновление `pts/qts/seq`. NotificationCenter даёт резервный путь с тем же детерминированным event ID. Повторный live/difference/UI event не создаёт вторую карточку.

Catch-up имеет дополнительные прямые ветки: `getDifference` и `getChannelDifference` записывают `new_messages` без `processUpdateArray`, а `channelDifferenceTooLong` заменяет локальный снимок канала через `overwriteChannel`. MOROK преобразует эти уже полученные payload в ту же dialog-map и подтверждает WAL до соответствующего `putMessages`/`overwriteChannel`. Секретные расшифрованные сообщения по-прежнему отклоняются общей eligibility. После durable new-event его ключ временно виден как pending до завершения replay, поэтому edit/delete из той же difference-пачки ставится в журнал следом за new и не теряется из-за асинхронной проекции.

Автоматическая карточка видимо отмечена в Памяти. Явное «Запомнить» превращает её в ручную, сохраняя версии, заметку и файлы. Удаление пользователем создаёт tombstone, поэтому повторный update не восстанавливает карточку. Автоматические записи ограничены 400 карточками и 90 днями; старые удаляются при следующей операции/вставке, а ручные карточки не участвуют в этой ротации. Общий предел остаётся 500 карточек. Архив не запускает скачивание: оригинал попадает в защищённое хранилище только когда полные байты уже доступны локально.

Отдельное действие «Импортировать недавние сообщения» предлагает выбрать один личный чат, группу/супергруппу или канал и повторно подтверждает источник. Оно читает на штатной storage queue до 100 последних строк с положительным message ID непосредственно из уже открытой локальной `messages_v2`, не вызывает `loadMessages`, MTProto и FileLoader. Для каждой строки восстанавливаются текущие TTL/custom params и применяются те же проверки secret/ephemeral/noforwards/restrictions. Подходящие снимки фиксируются одним commit индекса Memory; повторный импорт дедуплицируется по устойчивому ключу/fingerprint, а явный импорт может восстановить ранее вручную удалённый источник. Существующие ручные карточки не становятся автоматическими. Импортированные карточки входят в лимит 400/90 дней.

`org.morok.history.MemoryObserver.start()` подключается после нормальной инициализации Telegram, на главном потоке. На каждый слот ставится один долгоживущий observer:

- `didReceiveNewMessages`: резервно фиксирует новые сообщения только при включённой account-policy и наличии dialog ID в allowlist; scheduled/welcome/quick-reply режимы исключены.
- `replaceMessagesObjects`: снимок создаётся **только для уже сохранённых ключей**, до передачи работы в фоновое хранилище. Повтор получает тот же journal ID и применяется идемпотентно. Заметка/теги/завершение не перезаписываются.
- `messagesDeleted`: обычные ID сопоставляются внутри аккаунта вне каналов; канал использует собственный namespace. События scheduled-сообщений исключены.
- `historyCleared`: отметка удаления ставится только карточкам указанного диалога с `messageId <= maxId`.

Дополнительно `MessagesController.processUpdateArray` передаёт в Memory стандартные server edit/delete/channel-history события **до** постановки соответствующих изменений в Telegram storage. Этот путь работает и для обычных live updates, и для `getDifference`: редактирование снимается в неизменяемую ограниченную копию, событие атомарно записывается в зашифрованный входной журнал, затем Telegram продолжает штатную обработку, а проекция Memory обновляется на своей очереди. Первая загрузка membership и journal commit имеют предел ожидания по пять секунд; ошибка или timeout не отменяют server update, а фиксируют диагностический разрыв. Последующие `NotificationCenter` события остаются резервным путём; повтор имеет стабильный ID, редакция объединяется по fingerprint, повторная отметка удаления не переписывает индекс.

Оригинальная БД Telegram, `pts/qts/seq`, сетевые подтверждения и обработка серверного удаления не изменены. Удалённая карточка — отдельный локальный снимок с надписью «Удалено в Telegram, сохранено на устройстве».

Зашифрованный журнал ограничен **256 событиями и 8 МиБ на аккаунт**; одна запись не больше 768 КиБ, TL-снимок не больше 256 КиБ. New events одной update-пачки пишутся одним AtomicFile commit. До сериализации edit проверяется membership по последнему прочитанному/успешно зафиксированному индексу. Событие удаления больше 10 000 ID, неверный ID, переполнение, невозможный fsync или повреждение AEAD отклоняются. Потери сохраняют диагностический флаг аккаунта; предупреждение видно над списком и в экране хранилища.

Путь покрывает новые сообщения из основной update-пачки, прямые message payload обычного/channel difference, `channelDifferenceTooLong.messages` и стандартные `TL_updateEditMessage`, `TL_updateEditChannelMessage`, `TL_updateDeleteMessages`, `TL_updateDeleteChannelMessages` и `TL_updateChannelAvailableMessages`. Подтверждённая запись переживает смерть процесса до изменения `cards.tink`: запуск приложения читает журнал перед обычной операцией Memory, повторно применяет событие и удаляет его только после подтверждённой записи индекса. `differenceTooLong` без message payload сообщает лишь необходимость полного reset и не может восстановить никогда не полученный текст либо вывести точный набор удалений. Явный импорт ограничен последними 100 локальными строками и не пагинирует более глубокую историю; соседний сохранённый контекст отсутствует. Crash/fault-injection и catch-up на реальном авторизованном устройстве ещё не выполнены.

## Хранение, шифрование и сбои

Пути: `Context.getNoBackupFilesDir()/morok/memory/<stableUserId>/cards.tink`, `journal.tink` и UUID-имена зашифрованных оригиналов. Ни БД, ни журнал, ни оригиналы не лежат в кеше. Схема JSON версии 1 находится целиком внутри AEAD; поиск идёт после фонового расшифрования. Теги/заметки не публикуются во внешнем индексе и не отправляются в облако.

Используется проверенная библиотека **Google Tink 1.15.0**, `AndroidKeystoreKmsClient` и AES-256-GCM через Android Keystore. Формат ciphertext задаёт Tink. Собственный шифр/формат не вводится. Ключ на аккаунт имеет alias `morok.memory.v1.<stableUserId>`. AAD включает версию, владельца и назначение (`index`, `journal` либо UUID вложения), поэтому перенос ciphertext между аккаунтами/объектами не проходит аутентификацию. Нет запасного открытого ключа/keyset при неисправности Keystore. Поэтому Память доступна с Android 6 / API 23. Telegram как база сохраняет свой прежний minSdk.

Потерянный ключ при существующем индексе или журнале **не создаётся заново молча**. Чтение прекращается с видимым сообщением, ciphertext остаётся на месте. Явный зашифрованный перенос/экспорт и восстановление ключей не реализованы. После logout данные должны быть уничтожены, а не сохранены для повторного входа.

Journal I/O и проекция карточек используют отдельные последовательные очереди. Входное событие сначала фиксируется через AtomicFile, затем применяется к индексу; journal entry удаляется только после успешной идемпотентной фиксации карточки. `finishWrite()` может только залогировать ошибку Android, поэтому после него байты повторно читаются и сравниваются. Незавершённые файлы и сироты удаляются при следующем успешном чтении/записи. Одинаковые SHA-256 оригиналы одного аккаунта используют один зашифрованный blob; скан всех ссылок при cleanup сохраняет его до удаления последней версии. Экран хранилища отдельно считает карточки, версии, ссылки на сохранённые оригиналы, уникальные blobs и проблемные состояния. Сбой до фиксации индекса оставляет прежнюю карточку и journal entry для replay. Гарантия ограничена возможностями fsync/AtomicFile файловой системы Android, а не общей транзакцией с Telegram.

Logout сначала отзывает текущий объект сессии и все URI-grants, затем синхронно фиксирует небольшой revocation marker. Фоновая очистка дожидается всех journal writes, начатых до отзыва, и только затем удаляет ключ и каталог; новые операции уже отклоняются состоянием сессии. Если запись marker не удалась, выполняется синхронное уничтожение ключа. Если обе операции недоступны, исключение прерывает этот вызов до очистки UserConfig. Незавершённый marker требует очистки до любого повторного чтения тем же пользователем. Это предотвращает восстановление прежней Памяти при смерти процесса между logout и фоновой очисткой; ошибки удаления не снимают marker. Другой пользователь того же слота не может прочитать данные.

Manifest исключает backup приложения; каталог noBackup дополнительно исключает закрытые данные из штатной резервной копии. Защита от разблокированного root-компрометированного устройства не заявляется.

## Лимиты первой версии

| Ограничение | Значение и поведение |
|---|---|
| Карточки | 500 на аккаунт; автоархив занимает не больше 400, ручные имеют приоритет |
| Один импорт истории | до 100 последних positive-ID строк выбранного чата, только из локальной БД |
| Редакции | 20 на карточку; сохраняются последние по edit_date, более ранние удаляются |
| Размер TL-снимка | 256 КиБ; больший источник не сохраняется |
| Входной журнал | 256 событий / 8 МиБ; одна запись до 768 КиБ; overflow отмечает разрыв наблюдения |
| Заметка / строка тегов | 8192 / 512 символов |
| Расшифрованный индекс | 16 МиБ; переполнение отклоняется |
| Оригинал вложения | 8 МиБ; больший файл остаётся без устойчивой копии с явной отметкой |
| Весь аккаунт | 256 МиБ, включая индекс и оригиналы |
| Свободное место | резерв не менее 32 МиБ |
| Tombstones | 20 000 удалённых ключей, без автоматического вытеснения; новые удаления при полном лимите требуют дальнейшего решения хранения |
| Возраст | автоматические карточки — 90 дней с ленивой очисткой; ручные не истекают автоматически |
| Сеть | загрузки Памятью не запускаются ни по Wi-Fi, ни по мобильной сети |

Редакции сохраняют entities в TL, но первый просмотрщик цитат выводит обычный текст. Мультивыбор сообщений, полноценные отдельные фильтры тег/чат, общий вид нескольких аккаунтов, экспорт, OCR/ASR, мгновенное обновление уже открытой карточки и соседний контекст — следующий этап. Никакая версия не восстанавливается из не полученных ранее данных.

## Проверки

`tests/morok/run.sh` — 35 исполняемых JVM-проверок идентичности/повторов/изолированности tombstone ключа, reordered edit, journal/retention limits, границ размера/места и счётчиков общих blob-ссылок/состояний. `tests/settings` отдельно проверяет account-scoped allowlist, OFF default, persistence, bounds и изоляцию. Это проверки доменной логики, не имитация Android Keystore/диска.

`TMessagesProj_App/src/androidTest/java/org/morok/memory/MorokMemoryCryptoTest.java` — инструментальный тест реального Keystore/Tink: round-trip, изменение ciphertext, подмена AAD аккаунта. Выполнен на эмуляторе Android 16 / API 36; crash между journal/index и реальная delivery edit/delete требуют авторизованного device-теста.

Необходимый тест устройства до повседневной беты:

1. На A включить автоархив только для чата B. С аккаунта B отправить A текст и обычный файл меньше 8 МиБ; на A скачать файл, проверить автоматическую карточку, выполнить «Запомнить» для её ручного закрепления, добавить заметку/теги/напоминание.
2. Из B изменить сообщение несколько раз, затем удалить. На A найти полученные редакции и локальную отметку удаления, не меняя серверный список сообщений.
3. Очистить обычный кеш Telegram и перезапустить процесс; проверить цитату, просмотр расшифрованного файла через временный URI, источник/тему правильного аккаунта и локальное уведомление.
4. Повторить без предварительной загрузки оригинала; увидеть «Оригинал не скачан», без подмены миниатюрой. Затем скачать оригинал обычным действием Telegram, вернуться в карточку и выполнить «Повторить из локального кеша»: состояние должно стать «Оригинал сохранён» без нового сетевого запроса от Памяти. Сверить счётчики хранилища; две версии с одинаковыми байтами должны показывать две ссылки и один уникальный зашифрованный файл.
5. Проверить secret/self-destruct/view-once/noforwards/paid/restricted сообщения: команда сохранения отсутствует.
6. Проверить logout → другой пользователь в том же слоте → прежний пользователь: прежние карточки/URI недоступны. Прервать процесс между marker и стиранием.
7. Проверить запрет уведомлений/канала, Doze, перезагрузку, смену часовой зоны, перенос/отмену/завершение напоминания и app passcode.
8. Fault injection: нехватка места, невозможный rename, повреждение ciphertext, потеря Keystore, очередь >256 обновлений. Прежняя подтверждённая карточка/оригинал должны сохраниться, а потеря полноты наблюдения — стать видимой.

Эти сценарии устройства пока не выполнены; наличие исходного кода и успешная сборка сами по себе не подтверждают приёмку повседневной беты.

Источники API: [Google Tink](https://developers.google.com/tink), [AndroidKeystoreKmsClient 1.15.0](https://github.com/tink-crypto/tink-java/blob/v1.15.0/src/main/java/com/google/crypto/tink/integration/android/AndroidKeystoreKmsClient.java), [Android Keystore](https://developer.android.com/privacy-and-security/keystore).
