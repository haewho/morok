# Аудит записи кружочков

Состояние на 2026-09-06. База — Telegram Android 12.10.1 (7038), commit `62b56a07ca7e30e39f7fd00a6728d6bbd716ca1c`. Этот документ описывает код и проверенные локальные свойства. Он не подтверждает улучшение изображения на физическом телефоне или после доставки через Telegram.

## Фактический путь

1. `InstantCameraView` выбирает backend через `SharedConfig.isUsingCamera2(currentAccount)`. Camera2 использует `Camera2Session`, старый путь — `CameraSession` на Camera1.
2. Camera2 создаёт recording capture session с `TEMPLATE_RECORD`. Камерный `SurfaceTexture` поступает в существующий GL-путь `InstantCameraView.VideoRecorder`.
3. GL выполняет поворот, центральный crop и масштабирование непосредственно в input surface `MediaCodec`. Промежуточного Bitmap и постоянного CPU-копирования кадров в этом пути нет.
4. `VideoRecorder` кодирует `video/avc` с 30 FPS и интервалом ключевых кадров 1 секунда. Аудио остаётся штатным AAC-путём через `AudioRecord` и второй `MediaCodec`.
5. `MP4Builder` собирает квадратный MP4. На производительных устройствах штатная progressive upload логика использует `notReadyYet` и синхронизацию muxer.
6. Отправка проходит через `SendMessagesHelper.prepareSendingVideo`; `VideoEditedInfo.roundVideo` сохраняет `documentAttributeVideo.round_message`. Обрезка или редактирование могут запустить штатную дополнительную конвертацию, обычная запись кодируется один раз.

Штатные значения приходят из `MessagesController`: исходные defaults — 384 px, 1000 Кбит/с для видео, а server config `round_video_encoding` может их изменить. Это не доказывает универсальный серверный максимум.

## Реализованный экспериментальный путь

Переключатель по умолчанию выключен. При выключении размеры камеры, Camera2 request, выбор кодека и старые поля `VideoEditedInfo` остаются штатными.

При включении применяются кандидаты:

| Профиль | Желаемый выход | Желаемый видеобитрейт |
|---|---:|---:|
| Экономия | не ниже штатных 384 px | не ниже штатного, цель 1 Мбит/с |
| Авто | до 640 px | 1,5–2,5 Мбит/с |
| Высокое | до 720 px | 3–4 Мбит/с |

Перед записью resolver проверяет короткую сторону реального preview, поддержку квадратного размера при 30 FPS, диапазон битрейта AVC-кодека и `COLOR_FormatSurface`. Выбирается конкретный проверенный codec name. Профиль никогда не понижает штатное разрешение или битрейт. Если желаемая комбинация недоступна, выбирается следующий кандидат; если не подходит ни один — штатные параметры. Отказ `MediaCodec.configure()` также вызывает однократный откат к штатному кодеку до публикации события начала записи. Пользователь видит сообщение о снижении профиля.

Для Camera2 запрашиваются только объявленные камерой возможности: самый узкий AE FPS range, содержащий 30, continuous-video AF и EIS. При включении EIS явно выключается OIS, только если режим OFF объявлен, чтобы не требовать неподдержанную совместную стабилизацию. Если параметр не объявлен, остаётся default выбранного camera template. Если устройство отвергает собранный enhanced request, session повторяет штатный request без MOROK tuning. Camera1 получает только проверенный выходной профиль энкодера; новых обещаний AF или стабилизации для него нет.

Фактические выходные width/height, 30 FPS и выбранный битрейт передаются в `VideoEditedInfo` только в улучшенном режиме. Штатные значения 360/25 и 1 Мбит/с в legacy metadata сохранены при выключенном переключателе. Аудио, pause/resume, смена камеры, отмена, preview, секретные чаты, TTL, progressive upload и общий путь отправки не заменялись.

## Что пока не доказано

- Улучшение детализации, шума, смаза, экспозиции или стабилизации на OnePlus CPH2493 / Nord 3 с Android 16.
- Работа тех же профилей на старом Samsung с Android 10.
- Фактический постоянный FPS: диапазон вроде 15–30 допускает изменение частоты кадров камерой.
- Совместимость 640/720, pause, camera switch и максимальной длительности на физических камерах.
- Сохранение параметров после upload/download и распознавание получателем в официальных Android, iOS и Desktop клиентах.
- Отсутствие дополнительной серверной перекодировки. Для этого нужны исходный и скачанный файлы, а не только различие их container hash.
- Влияние EIS crop, нагрева, времени старта/остановки, CPU/GPU и расхода батареи.

До выполнения полевой матрицы функция остаётся экспериментальной и выключенной по умолчанию. Числа профилей являются кандидатами для испытания, а не заявлением о качестве или ограничениях Telegram.
