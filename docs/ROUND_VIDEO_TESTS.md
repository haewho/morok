# Проверка качества кружочков

Состояние на 2026-09-07. Автоматические результаты заполняются сборкой текущей ветки; полевые результаты требуют тестового аккаунта и физических устройств. Личные переписки не использовать.

## Выполненные локальные проверки

- `./scripts/check.sh` успешно проверил defaults, сохранение, migration schema 8, reset и нормализацию профилей Auto / Economy / High.
- `tests/camera/run.sh` проверяет 12 границ локального диагностического журнала и 7 integration-инвариантов: формат, очистку управляющих символов, отбрасывание повреждённых строк, лимит 40 событий / 32 КиБ, opt-in default, отсутствие network path и передачу только технических metadata.
- `:TMessagesProj_App:assembleAfatDebug` успешно скомпилировал интеграцию настроек, Camera2 и encoder hooks.
- `:TMessagesProj_App:connectedAfatDebugAndroidTest` прошёл 1/1 на Android 16 API 36.
- APK установлен на эмулятор. Экран открыт без входа; вручную проверены OFF default, включение, выбор High и сохранение `Experimental on` после cold restart. Падений приложения в logcat нет.

Эти результаты подтверждают сборку, запуск и сохранение настроек. Эмулятор не доказывает качество камеры, стабилизацию, реальные FPS или доставку кружочка.

## Полевой сценарий A/B

На каждом устройстве включить локальную диагностику и записать одинаковые 10–15-секундные сцены в трёх вариантах: чистая базовая сборка, MOROK с улучшением OFF, MOROK с улучшением ON. Сначала использовать OnePlus CPH2493 / Nord 3 Android 16, затем старый Samsung Android 10. Зафиксировать model, firmware, build SHA, front/rear camera, освещение, расстояние, профиль и наличие Camera2. После серии скопировать диагностический отчёт явной кнопкой и очистить его перед следующим устройством.

Сцены: лицо и мелкий текст при дневном свете; комната с искусственным светом; слабый и контровой свет; движение головы и рук; переключение front/rear; хлопок с короткой фразой для A/V sync. После короткой серии проверить pause/resume, отмену, preview/trim и текущую максимально допустимую длительность.

Для каждого локального файла выполнить:

```sh
ffprobe -v error -show_entries format=duration,size,bit_rate \
  -show_entries stream=index,codec_name,profile,width,height,pix_fmt,r_frame_rate,avg_frame_rate,bit_rate,color_range,color_space,color_transfer,color_primaries \
  -of json round.mp4
sha256sum round.mp4
```

Отправить в отдельный тестовый чат, скачать другим тестовым аккаунтом в официальном Telegram Android и повторить `ffprobe`/hash. Если доступны, повторить на iOS и Desktop. Проверить круглое отображение, звук, seek, отсутствие чёрных/зелёных кадров, crop, зеркалирование, детализацию текста/лица, шум, мерцание и A/V sync. Разные container hashes требуют сравнения потоков и кадров и сами по себе не означают перекодирование или потерю качества.

Сеть проверить отдельно: слабая сеть, включённый обязательный proxy, разрыв и восстановление связи, отправка во время записи, отмена и retry. Убедиться, что файл не подменяется после начала progressive upload и что новый код не создаёт собственный typing/`recordVideo` request.
