# Проверки

`scripts/check.sh` запускает доступные изолированные MOROK-тесты, сверку submodule SHA и whitespace checks. Они не заменяют полный Android build или устройство. Сборка чистой базы идёт отдельно от модификаций; текущие логи и результаты перечислены в `PROGRESS.md`.

До повседневной беты обязательны:

1. Установка рядом с Telegram: package, provider authorities, AccountManager contacts, deep links, launcher aliases. Обновление поверх предыдущего APK с той же подписью.
2. С собственными API-данными: вход/2FA, два аккаунта, текст, голосовые/видеосообщения, вложения, правки, реакции, группы, темы, камера и уведомления.
3. Память: включить автоархив только для тестового чата; разрешённый текст и полученный файл → автоматическая карточка → ручное закрепление/заметка/тег/напоминание → правка/удаление со второго аккаунта → принудительно остановить процесс между `journal.tink` и `cards.tink` → рестарт → replay, поиск, напоминание и правильный контекст. Вызвать offline catch-up через global/channel difference, включая new→edit→delete в одной последовательности и channel difference too-long snapshot; убедиться, что обычные `pts/qts/seq` продолжают двигаться. Отдельно импортировать локальный чат, проверить лимит 100, дедупликацию повторного импорта и отсутствие MTProto/media requests. Для отсутствующего оригинала сначала проверить cache-only retry без сетевого запроса, затем скачать его штатно и повторить; состояние и счётчики хранилища должны обновиться. Две версии с одинаковыми байтами должны иметь две ссылки на один blob, который удаляется только после последней ссылки. Затем очистить обычный кеш. Повторить с одной миниатюрой, noforwards/secret/TTL, повреждённым journal ciphertext, overflow >256, logout и другим пользователем в том же слоте.
4. Потеря Keystore, низкое место, kill во время записи, повторы событий и массовые операции. Не объявлять сохранённым файл до атомарной записи действительных байтов.
5. Каждый режим оформления сначала открыть и отменить на preview, затем применить и проверить точные Liquid Glass/animation значения и определение «Свой режим» после ручного изменения. Liquid Glass on/off в открытом чате: прокрутка/черновик, attachment/menu/navigation, светлая/тёмная тема, большой шрифт, TalkBack. Измерить отсутствие работы renderer на покрытых отключённых поверхностях.
6. Прокси до входа: ручной импорт и авто-выбор, отказ одного узла, смена Wi-Fi/mobile, отсутствие direct fallback. Звонки/FCM/mini apps проверяются отдельно.
7. Собственное устройство arm64 и отдельная российская сеть: записать дату, модель/API, оператор, Wi-Fi/mobile, каждый транспорт и результаты. Эмулятор не заменяет эти проверки.
8. Перенос настроек: экспортировать файл через системный picker, проверить отсутствие auth/account/chat/proxy/archive/Memory полей, изменить несколько локальных параметров, импортировать файл и сверить preview до подтверждения. Проверить Cancel, неподдержанную версию, повторный ключ, обрезанный и слишком большой файл; после применения убедиться, что исключения чатов сохранились, server read cursor не отправился и настройки пережили рестарт.
9. Диагностика кружочков: по умолчанию журнал пуст и выключен; после opt-in записать OFF baseline и каждый профиль, проверить plan/preview/output/bitrate/encoder и Camera2 request/fallback. Отчёт не должен содержать ID аккаунта/чата, media bytes или путь файла. Скопировать только явной кнопкой, затем очистить и подтвердить нулевой счётчик.
10. Профили приложения: до входа проверить экран и отказ сохранения/применения. После входа открыть preview и Cancel для каждого режима, затем применить и сверить оформление, video/GIF autoplay, все privacy-флаги и notification content. Убедиться, что качество кружочков, direct/manual/auto route и chat exceptions не изменились; «Свой» переживает рестарт, «Предыдущие» возвращают состояние. Получить FCM для private/group/channel/story при скрытом тексте, проверить lock screen, открытое приложение, второй аккаунт и отсутствие исходящего read/online/server-notification request. Имитировать ошибку записи и kill между хранилищами отдельно.

Невыполненные тесты не маркируются passed. Тест без авторизации подтверждает только доступные до входа экраны.
